# SeeCut 全功能 Agent 总体计划

日期：2026-10-20。状态：已获用户授权开始实施。按完整功能批次验证并更新现有 GitHub 功能分支；不以工具注册或单项测试代替全功能验收。

当前实施范围：优先 macOS 桌面端。按用户最新要求，Android 暂缓，不作为本轮交付或验收门槛；已完成的诊断改动仅保留历史记录。

SeeCut 的目标是让用户交代创作要求后，Agent 理解用户当前看到的内容，自主操作整个应用，跨生成、资产、画布、音频、剪辑、Flow 和导出持续执行，完成后交付实际作品。用户可以随时补充、暂停、停止或接着手动编辑。

本计划承接 [Agent 与内嵌 Flow 接入计划](2026-10-15-toonflow-agent-mcp.md)及[现有画布任务协议](../SEECUT-MCP-CANVAS-TASK-PROTOCOL.md)，按已确认的全功能覆盖和当前观看内容理解要求整理。历史文档的状态按当前源码重新核对，旧测试数字、旧版本状态和未完成事项不能自动转移到新候选。

## 两项硬验收标准

1. **每个模块的每个业务功能都能由 Agent 操作。** 建立逐项覆盖表，用户可执行的业务功能、页面导航、项目切换、对象选择与定位均纳入。一个功能可以由多个工具组合完成，但必须能在真实 App 中执行并核验结果。通过几条演示流程不能代替全量覆盖。
2. **Agent 理解用户当前真正看到的内容。** 发送请求时，获取与该时刻一致的页面、视图、选中对象、项目状态和必要画面。用户说这张图、这一段、这里时，Agent 能定位到正确对象；编辑后能回看实际结果。

全应用能力工具化与自主执行同时推进。用户给出任务并授予适用操作范围后，普通可逆步骤自主完成；涉及新增范围或具有独立确认门槛的动作，仍按对应规则处理。

## 当前观看内容如何交给 Agent

这部分作为独立产品能力建设，不能只传工作区名称或一张没有对象身份的截图。

### 发送时形成一致的上下文

| 信息 | 要回答的问题 |
| --- | --- |
| 页面和焦点 | 用户正在生成页、资产库、画布、剪辑还是 Flow；是否打开预览、属性面板或弹窗；当前操作区域是什么 |
| 项目和对象 | 当前工程、文档、画布、轨道、片段、图层、节点及素材身份分别是什么；哪些对象被选中或明确引用 |
| 当前视图 | 图片缩放/平移、实际可见范围；时间线可见时间范围、播放头和预览帧；Flow 的视口和可见节点；列表筛选、当前预览与可见结果 |
| 实际媒体 | 与当前状态对应的画面、局部裁图、视频帧；需要判断声音时取适用音频或转写，波形不能代替声音内容 |
| 状态和版本 | 文档与选择版本、视图版本、未保存修改、忙碌状态、相关后台任务；画面对应哪个版本和时间点 |
| 能力和限制 | 当前能读取和操作什么、模型是否能看图或听音频、当前授权及预算适用范围 |

先读取轻量宿主状态，再按用户问题补必要结构和媒体。默认只取 SeeCut 内相关内容，不截取整个桌面，也不自动上传整个素材库或完整长视频。

用户请求、上下文和预览属于同一份发送快照。快照内保留对象 ID、视图位置和必要坐标映射，让模型看到的画面可以对应到工具操作对象。取得预览时若文档已改变，则刷新或返回过期状态，不拼接不同时刻的截图与对象信息。

发送时的原观察需要与后续执行状态分别保留。普通文档输入已携带原生点击发送瞬间的完整观察身份，按原inputId保存和重取；首次contributor根据真实input.applied找回原输入，核对后才进入现有选择与操作规则。Task create/update走各自原人类来源，单独接入。App页导航代次随实际重新打开变化，防止A→B→A认领旧结果；页面stamp绑定筛选、选择、表单和当前预览目标，后台进度与余额刷新作为带来源的普通读取结果。初始观察不能被误用为长任务所有轮次不许变化的工程版本，任务后续仍由原操作及独立回读推进。

### 无工程页面的接入顺序

本批源码增加独立的只读App范围，覆盖生成页、个人/团队素材、模板、账户/积分、设置及项目列表；原画布、剪辑和Flow继续保留文档协议。普通页面使用真实账户与AppSession，不填充替代的projectId。精确合同见[App页面读取协议](../agent/app-read-protocol.md)，源码和合成证据继续与真实App验收分别记录。

- 先从Cloud现有缓存和UI当前值形成有界 `AppPageSnapshot`：页面、浮层、筛选、选中/预览目标、分页及 `pageStateId`；不在40毫秒刷新路径读取整个库或扫描磁盘。
- App读取许可与文档写许可分别核对，绑定当前账户、appSessionId及请求状态。设置、密码、验证码和token只投影安全状态；不整体序列化设置结构。
- 通过 `app_context`、`page_items` 与按需 `page_preview` 提供内容。项目列表用宿主管理的opaque条目身份映射真实路径，工具不接收任意路径。
- 筛选结果集、实际屏幕可见项、真实焦点分别记录。当前各页缺少ScrollView裁剪/可见卡片和通用焦点桥接，先明确未知，再补真实测量；focus-return-*只代表焦点返回意图。
- 图片预览绑定当前目标、账户与preview token；视频/音频当前只有缩略图并交给外部播放器，不宣称读到了正在播放的帧或声音。媒体预览与Agent共存需单独处理，只读预览不连带开放登录、支付等浮层。

跨工作区任务交接继续单独实现：先关闭原推理/费用与写入，核对可信目标、原产物和固定版本，再建立目标文档范围。新页面读取不使旧TaskGrant自动获得新工程权限。

Flow项目列表、创建和打开已有业务API与完整Web包装器，下一步补项目级许可、列表上下文、原创建操作恢复和新Doc采用确认。创建当前每次分配新UUID且没有原操作查询，超时不能重发创建；服务打开session与真实Flow文档session也不同。列表中的local副本不等于当前云账户归属，通用view-ready连错误页也会发送，都不能用作交接成功证明。上述仍为源码调查结论，3条路线保持未映射。

### 理解和执行的规则

明确附带的对象优先，其次是当前选择、打开的预览或焦点，再结合当前可见区域和工程内容。多个对象同样合理且会明显改变结果时，集中问一个必要问题。

区分用户此刻在看的对象和任务已经绑定的目标。用户切页后刷新观察信息，已经运行的任务仍绑定原工程和素材版本；不能把迟到结果写到新打开的文档。结构信息与真实画面互补，模型不支持相关媒体时明确降级，不声称已看过或听过。

性能采用按需裁图、分页、去抖和基于版本的预览复用。上下文正确性与响应延迟、图片体积、模型实际用量一起验证，不在每个输入事件上传整屏。

## 统一业务工具与 MCP

沿用现有 Rust/Slint、原生图片画布、音视频引擎及内嵌 Toonflow。公开 seecut 负责业务命令、MCP、当前 App 绑定、权限和保存；私有 seecut-agent 负责目标理解、编排和专用工作流；COTO 提供通用执行底座。

工具直接调用当前 App 的受控业务接口，与手动操作共用同一份项目状态、撤销历史、保存和资产业务。不能通过另开项目副本来假装控制当前页面；不能让 Agent 直接改工程 JSON 或通过任意脚本绕开业务约束。

工具定义同时说明输入输出、适用对象、读写属性、版本前置条件、异步任务、取消、错误与结果验证。按模块和任务发现所需工具，完整功能覆盖不要求一次把所有工具 schema 塞进模型上下文。

先复用现有接口与 helper，再补受控边界。时间线命令、字幕、配音、通用资产及视频导出是当前主要接入缺口。UI 导航和视图变化也有明确接口；业务执行以稳定对象身份为准，避免依赖屏幕坐标模拟点击。

## 长任务和自主执行

在现有会话与操作日志之上建立持久化创作任务。任务关联用户目标、步骤和依赖、目标工程与素材版本、原操作及异步任务身份、检查点、用户补充、授权与预算、实际产物和下一步。

会话用于交流；创作任务用于执行和恢复。先用轻量任务记录关联现有画布文档、剪辑工程和 Flow 项目，不要求立即迁移成一个新的大型统一项目格式。

单轮推理和一次工具调用保持合理上限，由任务编排器在获得明确结果后继续下一轮。超过两分钟的生成或导出以后台任务身份跟进；不能只延长一次模型超时来冒充长程执行。App 退出后哪些本地任务停止、哪些远端任务继续，必须有明确状态；重开后查询原任务，不重新提交。

任务授权覆盖明确的业务范围，普通步骤无需用户逐项指挥。撤销写权限立即停止后续写入；对象、工程、账户或预算超出原范围时重新处理权限。对具有独立确认门槛的动作，Agent 可以完成准备并在相应动作前请求确认。

用户补充要求优先影响未完成步骤。已完成素材和产物按身份复用；暂停和停止明确区分。遇到结果未知时查询原 operationId/jobId，不换身份重试；现有各业务账本继续作为事实来源，任务层只关联它们。

任务完成须同时满足目标、操作结果与产物验证。最终返回实际作品、可继续编辑的工程、保存位置和未完成项。聊天结束、模型返回最终文字或导出提交成功均不代表整项任务完成。

实现先接现有 runtime 的轮次终态和 managed 预算收尾，再由串行 `TaskCoordinator` 调用原 `sendInput`。每次调度先保存稳定输入身份和控制代次；恢复时查询该输入是否已被接收。结果未知、费用未确定、异步任务未结束、授权失效或存储不足时禁止继续派发。模型通过受限检查点提出计划变更和完成声明，宿主核对原操作及产物后才更新任务。

第一批保持当前工程会话绑定，实施持久状态、分轮调度、补充要求与暂停/停止/恢复。当前 controller 在文档身份变化时会断开；跨画布、剪辑和 Flow 的自动交接另需宿主事务，先结束原轮次和费用、保存交接身份、激活目标、核对新 context，再绑定新会话。完成调度基础不能直接认定跨模块已贯通。

现有原操作 journal、COTO 事件与 managed 记录都有容量上限，第一批在副作用发生前检查并明确停止。后续归档需保留原身份、完整回执与 UNKNOWN 记录，采用有总量限制的不可变归档和原子索引；不能只增加文件上限或删除未知记录。应用退出后由下次打开恢复，本地 runtime 随 IPC 关闭，当前不宣称退出后继续执行。

## 分阶段交付

沿用原总顺序，将已实现部分直接复用。以下是能力与验收阶段，不要求重新开发已有资产库、画布或 Flow；工具覆盖、上下文和长任务基础可以在依赖明确后并行准备。

| 阶段 | 交付内容 | 通过标准 |
| --- | --- | --- |
| 0 稳定当前候选 | 成对版本、权限热切换、浮层、CI、必要原生交互和当前生成入库链 | 精确候选的实际结果、失败恢复和检查记录完整；开发副本与正式分发包分开 |
| 1 Agent 基础 | 每次发送的页面上下文、能力发现、任务身份与进度骨架、现有账户积分和权限基础 | 同一任务可追踪；当前对象准确；普通步骤能按授权继续，撤权立即生效 |
| 2 现有资产库接续 | 图/视频/音频统一检索与引用，固定版本、来源、跨工作区导入及幂等登记 | 从库到画布/Flow/时间线、结果回库和重开一致；缺失或版本冲突有明确结果 |
| 3 原生画布操作 | 全部现有画布业务工具、结构与真实预览、选区和评论改稿 | Agent 按用户指代选对对象，实际编辑、撤销、保存重开和导出正确 |
| 4 Flow 完整接入 | 完整节点/项目/执行/产物能力及原上游迁移范围；与资产和生成的受控接续 | 可运行工作流正常与失败路径实测；原清单逐项更新，不用一条成功流代替完整范围 |
| 5 全应用 MCP 补齐 | 生成、通用资产、完整画布、音视频时间线、字幕、配音、设置、保存导出和视图控制 | 全量功能覆盖表每行均有真实入口、可发现工具、权限/版本规则及执行结果证据 |
| 6 Agent 全流程创作 | 持久任务编排、中途调整、异步等待与恢复、跨工作区执行、最终作品验证 | 用户一次交代目标后完成整项任务；用户切页、断连、重启和部分失败不串项目、不重复付费、不虚报完成 |

阶段 5 的时间线、字幕、配音和视频导出接入可按独立模块准备；不必等待阶段 4 每个扩展能力全部验完才编写它们。最终整合遵循共享协议和实际依赖，写入与集成由主代理串行协调。

原 Flow 76 项是历史迁移覆盖清单，包含图/节点/媒体、3D、Agent/MCP、文档和设置扩展等范围，继续保留。当前已改为嵌入固定版本 Toonflow，应按实际版本重新映射并补充遗漏；旧的 0/76 记录不能直接当作今天的进度，也不能因嵌入源码存在就全标完成。

复用已调查的 ComfyArt 结构读取、真实画面、选区改稿、资料集合及元素拆分流程，保留 SeeCut 现有画布。参考实现不等于 SeeCut 已具有相应工具或模型效果。

## 总体验收

必须同时完成全功能逐项验收、跨模块任务验收、当前观看内容理解验收。三者分别记录，不能相互代替。

- **全功能覆盖**：逐行从 Agent 发起，业务发生实际变化，回读验证；适用时测试撤销重做、保存重开、失败和恢复。工具存在而实际不可执行的行保持未通过。
- **当前观看内容**：覆盖不同缩放/平移、时间线范围、播放头、选区、预览和弹窗；验证用户说这张图/这一段/这里能定位正确。用户切页、手动编辑或重排后，过期图片和结构不会混用。
- **图片任务**：从素材库选图、按意见修改画面和文字、保存可编辑工程、正式导出入库并回看。
- **音频任务**：从用户要求或脚本生成/处理声音，调整时长和音量，验证实际音频及导出结果。
- **完整视频任务**：给定商品图或片段，生成补充素材、制作封面、配音与字幕、安排时间线、导出成片，并交付工程、成片、封面和位置。
- **长任务恢复**：任务跨多轮及超过两分钟；用户中途补充、切项目、暂停、停止、断连和重开；已完成步骤复用，未知结果只查询原操作。
- **真实作品质量**：图片看渲染，视频检查完整播放及关键帧，音频实际试听，字幕检查时间与内容；hash、HTTP 成功或工具回执只证明对应步骤。

每个任务按需选择明确的模型、素材和预算；本地合成供应商验证控制链，真实供应商、质量和实际计费使用各自证据。

## 正式分发和执行边界

功能收尾后交付配对的公开应用与私有 runtime，核对兼容版本、签名、安装更新、数据保留、回退与许可。账户、生成、统一积分和生产服务按现有方案验收，不另造账户或计费来源。PR 合并、生产部署和正式发布分别确认结果。

用户已授权按本计划实施、自行处理可恢复问题并分批更新 GitHub，包含相关 CI 修复及功能分支推送。PR 合并和正式发布仍按相应授权与平台规则执行。原生测试必须使用不影响用户鼠标、键盘和焦点的环境，缺少该环境时保留实窗待验。开始及实质边界读取新鲜周额度，剩余不超过 30% 时按用户停线要求保存断点并停止。

公共 seecut 保持原生 UI、业务接口、MCP 与验证；私有 seecut-agent 保持 SeeCut 专用编排、提示词及工作流；COTO 只承载可复用通用能力。实现任务可按不重叠模块分派，主代理负责技术和产品决策、审查、串行集成与最终验收。
