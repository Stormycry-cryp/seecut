# Agent 视频导出接入计划

状态：公共27c414ee已交付发布前回调、StrictLocal媒体输入、输入副本及成片独立核对，并修复MP4尾帧时长为0的问题。当前新增内部发布控制器、源帧8/10位核对及renderer共用渲染计划，完整模块检查为media80、export43、host138，新增检查均包含在各模块总数内。Agent工具、原生生命周期和个人库固定版本交付仍在接入。精确版本和适用检查见[导出QA](../testing/main-qa/2026-10-21-clip-export/README.md)，公开wire见[导出协议](../agent/clip-export-protocol.md)。原生界面和适配由实际Astra/high实施，主代理负责协议、审查与集成，Android暂缓。

目标：Agent 导出当前活动时间轴，持续查询原任务，取得可读成片和个人库固定版本，再向用户交付。复用现有 `Exporter`、`concat-export` 渲染器、原操作回执和资产登记恢复，不增加第二套渲染器或业务历史账本。

## 已确认的真实接口与缺口

- `concat-host/src/export.rs` 的 `request` 从原 Session 构造活动时间轴请求，`Exporter.begin` 持有现有单任务 slot。现有整段导出从 0 到活动时间轴结尾，不代表合并全部时间轴。
- `concat/src/panes/export.rs` 已接 MP4、H264/HEVC/AV1、8/10 bit、短边 720/1080/1440/2160、24/30/60 fps 和三档画质。它在 worker 渲染成功后登记个人库，但面板没有保留原注册身份与固定 AssetReference；登记失败仍显示 Done。
- 当前请求复制媒体路径，未冻结媒体字节；遮罩目录、栅格标题和用户效果包/LUT 也是实际输入。`concat-export` 还会读取全局 Catalogue，不能只复制媒体便承诺来源固定。
- 渲染返回路径不含独立新开文件的摘要、实际尺寸/帧率/时长或解码证明；取消请求也不能证明没有输出。既有 `concat-host/tests/export.rs` 的真实渲染和完整音视频解码思路可复用，适用测试在实施时执行。
- 效果包允许 FFmpeg 模板 literal，不能假定外部文件只有声明的 LUT。音频链在 flatten 时已形成字符串，冻结 Catalogue 还须覆盖该阶段。首批对不能枚举并冻结外部依赖的效果明确拒绝，不能静默省略，也不能接收模型给的滤镜字符串。

## 实施决策

1. 首批目的地采用应用管理的 clip-exports 目录，由应用分配输出身份。模型只能给显示名称与封闭的原生编码选项，不接受文件系统路径、工程 JSON、滤镜代码或 shell 命令。任意目录交付沿后续可信 UI 选择接入。
2. 活动时间轴、工程/文档身份、原 revision/selectionRevision、来源摘要、账户与会话，在原授权链内冻结。构造快照时验证需要的媒体和标题均已进入请求，不能静默省略缺失输入。
3. 能传入固定 Catalogue 的窄渲染入口已完成，原 `render` 接口兼容。已在有界受控临时目录复制并核对媒体、遮罩和栅格标题，重写该次请求所用路径；首批只支持无外部目录和LUT的捕获效果包，不能完整处理的自定义包明确拒绝。副本前后核对实际字节摘要与来源，不能以文档摘要代替媒体摘要；媒体自身额外I/O已通过SelfContainedLocal策略约束，任意外部模板/LUT的支持仍须另行冻结。
4. typed 导出操作沿原操作 ID、严格序号、精确许可、WriteRegistry 和 Receipts；进度、取消与最终结果属于同一操作。原Job的cancel_handle只取消原任务，禁止迟到调用全局exporter.cancel误停新任务。最终发布前由同一渲染器调用窄发布许可接口：原操作Pending→Publishing与撤权/停止竞争，取消先成功则禁止发布，发布先成功则允许记录原真实结果。不能以AtomicBool最后一次检查声称已消除rename窗口。迟到成片保留原归属，不写入新文档或新账户的交付状态。
5. 成功至少包含实际成片新开、普通文件与有界字节数、SHA256、媒体 probe、可解码视频及需要的音频，再核对相同内容的个人库固定版本。结构与解码检查不能代替作品画面、完整播放和声音验收。
6. 成片完成但登记失败，保留原注册身份和受管副本，只重试原登记；不能换操作重新渲染来消除原 UNKNOWN。原回执重启丢失时，当前文件或资产存在不补造历史成功。
7. Task 增加原视频交付类型，并复用现有任务调度器查询原长任务。运行中不占用单次 MCP 请求直至完成；不得靠模型反复提交或延长一次请求超时。现有保存与 Flow 的交付证据分别保留。

长任务授权须区分受理期限与原任务控制权。原写请求的短截止时间只允许在有效期内受理一次；成功受理后的原导出不能因一次MCP请求结束而失去身份，也不能靠重新发送或延长原请求获得权限。后续由绑定原操作、账户/会话和写权限代次的控制对象响应撤权与停止，并参与最终发布仲裁。具体wire字段、失效条件与持久Task查询规则在向Agent开放前单独定稿和验证，不能直接照搬短保存任务的worker截止时间。

内部PublishPermit/PublishRevoker已通过12项逻辑检查，实际生命周期仍由原生接线批验证。`render_facts`与同一renderer共享转场、音频成员和帧数计划，避免另算期待或从成片反推；成片要求所有实际源帧匹配8/10位。上述模块通过不表示Agent工具已经开放，原任务回执、取消与登记恢复、当前成片独立回读及clip-video Task均按公开协议接入。
