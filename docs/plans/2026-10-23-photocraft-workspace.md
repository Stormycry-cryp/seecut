# PhotoCraft 完整图像编辑工作区接入

日期：2026-10-23。用户已授权整套接入 PhotoCraft 的画布及 PS 相关功能，并按 SeeCut 的视觉规范调整界面，统一接入 SeeCut Agent。完整上游与开发入口已接入功能分支，当前继续验证实时文档控制与画布观察；尚未替换默认画布。

## 目标与约束

- 复用完整编辑工作区：画布、图层、选区、蒙版、文字、矢量、画笔、滤镜、调整、历史、文件与其他上游已有交互。以固定来源的实际功能清单验收，不能只迁移几个算法或重写一个功能子集。
- PhotoCraft 的编辑界面和 Agent 必须操作同一个实时 Session。SeeCut 保留账户、生成、品牌素材与资产库、任务、权限、收费及交付的业务权威。
- 前端由实际 Astra 子代理完成，新任务使用 medium；实现配置、后台业务与测试由 Sol high 承担；主代理负责方案、产品决策、审查、集成与验收。
- Android 暂缓。不得抢占本机鼠标、键盘、焦点或播放声音。优先离屏和独立 CI 窗口验证。
- 周额度剩余 50% 时停线。清理限于本任务明确的缓存与已被替代的构建产物，操作前核对路径、占用和当前消费者；保留当前候选、源码和验证证据。
- 旧画布与原 `.comp` 工程在迁移验证通过前继续可用。不得静默扁平化旧项目，不直接修改用户原件。

## 固定来源与已经核实的边界

PhotoCraft：`https://github.com/storytold/photocraft`，固定提交 `ff4738810134d7f7e68b49f2e4f231b686282ff3`，workspace 版本 0.14.0。实际源码把 doc、ops、compose、format、io、engine 与 ui-egui/automation 分层；应用使用 Rust、egui/eframe 0.36 和 wgpu 30，最低 Rust 1.95。SeeCut 当前使用 Slint 1.17.1、wgpu 29、Rust 1.93。

代码采用 MIT OR Apache-2.0；上游品牌图形不在代码许可内，派生 SeeCut 界面须替换品牌。保留代码来源、许可证、NOTICE 和实际使用资产的归属记录。

默认 CLI/MCP 使用自己的 headless Session；连接运行中编辑器的 Bridge 才能修改用户当前文档。现有 Bridge 可以调用实时 engine 和读取 UI，但截图、文档 revision、视口未组成一个原子快照。`command_batch` 也不提供整批回滚。SeeCut 仍需补当前内容快照、权限、幂等和长任务恢复合同。

原生工程为 `.pcraft`。PSD/PSB 是交换格式，部分文字、智能对象、混合与调整会产生损失警告，不能作为所有旧 `.comp` 语义的无损中转。上游没有已验证的普通成品图自动语义拆层流程，生成式改稿和品牌素材复用仍由 SeeCut 接入。

## 工作区与职责

- SeeCut 功能分支：`codex/seecut-photocraft-workspace`，基于 `247334c2f37cde265b2424923fd3386e23dcc0f3`。
- `integrations/photocraft/`：来源锁、完整功能基线、SeeCut 适配补丁与验证说明。
- `external/photocraft/`：按固定来源和补丁生成的可重建依赖副本，忽略提交；不提交构建缓存。
- 接入脚本：校验固定提交、应用受控补丁、构建编辑器与离屏验证，打包为 SeeCut 自有组件。
- 原生入口与生命周期：SeeCut 管理编辑工作区、就绪/关闭、当前文档、工程路径和恢复；退出或切换保留真实未保存提示与完成回执。
- Agent 适配：将实时编辑器的状态、命令、选区、预览与结果接入现有受控 MCP/Task，不直接把上游 bearer token 或任意文件写能力暴露给模型。

## 实施顺序与验收

### 1. 固定完整上游并建立基线

记录实际 engine command、UI action、菜单、工具/面板与文件能力；生成来源与哈希，明确上游本身未实现或有限制的行为。沿用已有固定来源与适配补丁方式，避免复制一份无法追踪的源码。

验收：干净副本可以恢复相同来源，补丁可重放；清单能发现误删菜单、工具或命令。测试证明只对应实际执行的层级。

### 2. 验证完整编辑器的宿主方式

优先评估完整原生编辑工作区，保留上游工具和对话框，不重做全部 Slint 前端。同一个 Slint 窗口内嵌涉及 eframe::Frame、事件循环、输入与 wgpu 版本边界，不能视作现成 Widget。先完成有证据的宿主选择，再接产品入口；必要时使用 SeeCut 管理的编辑窗口，归同一产品、任务与实时文档。

验收：构建真实完整编辑器，离屏渲染并检查；验证键盘、输入法、拖放、弹窗、缩放与焦点归属。独立编辑窗口与真正同窗内嵌分别记录，不能互相代替。

### 3. SeeCut 视觉和基础产品接入

以现有 `ui/theme/` 与 SeeCut UI 组件为当前视觉来源，调整配色、字体层级、间距、边框、圆角与 SeeCut 品牌；保留原有工具/面板和快捷键能力。连接图像工作区入口、工程保存/打开、资产导入和导出入库。

验收：检查深浅色、常规/窄窗、完整工具与对话框；从素材进入编辑、保存后重开、导出后实际读取资产均通过。只有构建或截图不算完整编辑验收。

### 4. 统一 Agent 与当前观看内容

为实时 Session 建立稳定编辑器/文档/图层身份，文档、选择和视图版本，以及对应的干净画布图和必要局部图。读取与修改前后核验原身份与版本；操作后台 job 使用原任务身份等待和恢复，未知结果不能重发写操作。

接入命令发现、启用条件、封闭参数和受控执行。先验证建立文档、图层与文字、选区局部修改、撤销/重做、保存、导出与回看；再按完整清单扩展。UI 输入仅用于上游无法用语义命令完成的交互。

验收：Agent 与用户手动编辑同一文档；旧版本、撤权、取消、文档切换、重复请求与后台失败正确处理。模型实际观看、生成内容和视觉质量分别验证，不以合成端点替代。

### 5. 旧工程迁移与完整功能验收

明确 `.comp` 到新文档的逐项映射、无损条件和不支持项。原件保留，转换写新工程；有损必须报告并保留旧画布打开路径。运行固定上游功能清单及 SeeCut 业务矩阵，补缺后再调整默认画布。

验收：旧工程真实重开与编辑、编辑历史、PSD/原生保存边界、资产身份、跨功能长任务、退出恢复与正式包分别有证据。当前候选仍为 Draft，未获覆盖授权不得合并或发布。

## 已保存 Photo 工程的 Agent 绑定决策

首个上层切片沿用工程保存后才能建立文档会话的现有规则，未保存 Photo 不生成临时 project_key。父级后台只从 child 的真实 backing 事实解析规范路径；标题、旧 Canvas 或模型提供路径均不能代替文档身份。历史继续按真实规范路径关联，同路径原子保存更换 inode 不重建 history key。

另存为、backing 关联重绑或丢失已接入 checked document_generation；同路径正常原子保存保留 generation。同一 UI 回调拒绝旧 expected，避免父级检查后另存为的竞态。真实 backing 四字段、恢复 sentinel 与后台双读文件核验已实现，保留原有账户、权限、精确批准、Task 与原操作回执链路，不增加独立账本。这些内部能力尚未接入父级 MCP/Task。

当前七补丁候选的引擎 2 项、UI 47 项、打开/解绑 3 项、真实套接字 2 项，以及原生宿主 18 项测试均实际通过；宿主 all-targets 严格 Clippy、联测例子编译和 workspace fmt 通过。macOS 非 UTF-8 文件名夹具被 APFS 拒绝，未覆盖对应 helper 路径；Linux 保留实际用例。此前 Linux 联测在完整编辑器编译阶段因已发现的保存/退出路由问题主动取消，已验证的 TERM/KILL 两项进程隔离回归保留。新例子使用 app.save 与封闭 seecut.close，实际进程和像素结果需新运行验证。

当前七补丁 desktop/CLI 已完整重建并独立核对真实产物，官方 HEIF 保留；实际 CLI 仍注册 935 个命令且静态候选无缺失。该来源的本机凭证为 `.toonflow/photocraft-build-04/`，不能替代真实窗口、完整功能或模型任务验收。

## 10 月 26 日文档结构读取

父级已注册 `photo_state`，只接受原 `projectId` 与 `documentSessionId`。已保存 Photo 可以通过原 Doc 读取授权及 Settings 客户端授权读取结构；两条授权都没有媒体或编辑权限。Photo 的能力发现只列 `capabilities`、`photo_state`，不把旧 Canvas、Clip、Flow 工具列为 Photo 功能。服务端仅同步工具词表，不开启 Photo 的托管 Agent 连接或发送。

请求先在 UI 核对原实例、文档、账户、来源及读取许可，再进入唯一 Photo 后台 worker。worker 验证原文件历史键与 host/doc/generation，重新读取真实 backing 和完整文档身份，返回后再次核对原许可与来源。单个待处理请求持有原五秒截止时间；取消、切源、另存为、文档换代或过期均不能把旧结果安装到新来源。文件操作不进入 UI 线程，五秒只约束结果有效期，不承诺中止底层文件操作。

返回有界的文档、图层、选择及历史元数据，原生 u64 和规范路径留在 Rust 内；opaque handles 仅引用原读取，不自动替换成新的文档或图层。结果明确 `metadataOnly`、`editAvailable:false`，不构成像素、实际显示或编辑能力的证明。后续写解析器目前仅作为 `cfg(test)` 候选回归保留，没有生产写入口。
