# SeeCut 本地编辑器 MCP：M2 最小实施方案

状态：供主审接续的方案，尚未开放写工具。依据 M0 契约及 M1 分支 `e2014a5` 的现场源码；M1 的新 Cocoa App 退出实测、活跃剪辑与手势原生覆盖仍分别记账。

## 目标与顺序

先排除 native 与旧 `concat-api` 对同一工程的独立可写会话，再通过可信 App 授权，在当前 UI 会话完成一次具名、可撤销的画布空间平移：明确已选单一图像层的稳定 ID，`dx/dy` 为文档像素的有限、有界数值。沿已有变换提交与历史增加薄类型化入口，保留缩放、旋转、翻转等其他 transform 分量及现有 linked mask 语义。图层叠放排序不在首个动作范围。

顺序为所有权基础 → 全部现有写会话接入 → 授权与一次 UI 提交 → 实际闭环。前两项未验收时写工具不发布到 capabilities。M2 不同时扩充 SVG、生成、导出或通用命令入口。

## 1. 工程所有权基础

改动集中在 `src/crates/concat-host/src/` 的小型私有所有权模块及 `Session` 接口。采用 RAII 所有权守卫，非阻塞尝试 OS 独占文件锁；冲突时有类型化错误，不等锁、不抢占旧所有者。可优先评估仓库 Rust 1.93 已支持的 [`File::try_lock`](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)，实际 macOS/Linux 行为以子进程测试为准。

- 工程文件夹按实际规范化目录身份取锁；已有 `.comp` 按规范化父目录和最终文件目标取锁。新目标先确定父目录身份，并发创建同一目标也必须争用同一身份。相对/绝对路径、符号链接及本机大小写别名须映射到同一锁，不能以字符串 lowercase 代替文件系统验证。硬链接别名的处理方式在本阶段定点核对，未解决时拒绝有歧义目标，不默许两份状态写入。
- 锁对象与原子替换的文档文件分离：保存不能通过 rename 换掉被锁 inode。正常释放不删除仍可能被另一个进程打开的锁文件；锁文件存在不代表占用，依据 OS 锁。
- guard 持有到会话关闭且旧保存 worker 已完成或失效。自动保存 worker 必须持有同一 owner，不能只靠 UI 字段寿命。
- 未保存画布先由当前 App 独占；首次自动保存、另存和重绑定，在写入目标前取得其锁。SaveAs 的旧新身份相同时复用 owner，不重新夺锁。新目标失败时保留当前绑定/文档/历史及旧锁；切换成功后旧 worker 仍受原 owner 与代次检查约束。
- 同 canonical 工程已被当前 Session 持有时，open 复用/返回已打开会话，不能先取得第二个 owner 再把正常重开当冲突。同进程的另一独立 writer 仍拒绝；实现时核对独立文件描述符的锁语义，必要时补进程内所有者表，不使用复制句柄取得第二个逻辑 owner。

定点验证：两进程同目标或并发创建同目标一胜一拒；符号链接/相对路径/大小写别名不能绕过；当前 Session 重开及同身份 SaveAs 正常复用；不同工程可同时持锁；owner 退出后可再次取得；文档原子替换期间第二 writer 仍被拒；旧 worker 未结束时锁仍有效。使用小临时目录和子进程，无媒体下载。

## 2. 现有 native / API 写会话全部接入

| 文件或组件 | 改动边界与直接验证 |
| --- | --- |
| `concat-host/src/session.rs` | `Session::open/open_info` 在读取可写状态前取得 owner，保存和关闭保留它；解析错误不留下有效占用。 |
| `concat/src/studio.rs` | `open_project` 当前会预读一个临时 Session 再正式打开；同 canonical 当前工程直接复用；其他工程取得一次候选会话，关闭旧工程成功后采用它。打开冲突/解析失败保留原工程。`SaveLane` 和异步保存持有 owner，延迟回包不能写进新会话。 |
| `concat-api/src/lib.rs`、`message.rs` | `adopt/open/create/close/save` 共用 Session 所有权，规范化 keys 与锁身份一致；冲突回可分支错误。API 已持工程时 native 拒绝，反向也成立。 |
| `concat/src/panes/canvas.rs` | `.comp` 打开、保存、另存、首次自动绑定、关闭及异步写快照共用 owner；仍沿现有序号/文档代次规则，不改历史算法。 |
| `concat/src/host.rs` 及既有服务连接 | 盘点实际旧服务会话入口，确保每条 writer 都接入；MCP 写入继续走窗口持有的 Studio，不让旧 API 另开一份状态。 |

既有会话接入策略：升级后的进程在创建 Session 时即持锁；在进程内已有会话必须在开放写 capabilities 前确认 owner。失败时禁止该会话写入，保留未保存状态交用户处理，不能后台覆盖或关闭。未升级的旧 App/服务不会遵守新锁：启用写功能的验收环境先确认它们已正常保存并关闭，再启动统一版本；不能声称 OS advisory lock 约束了旧二进制。

验收：native/API 双向抢占拒绝且原文件不变；API 关闭或 App 正常退出后另一方可开；失败的工程切换保留原会话；延迟自动保存与关闭/另存的真实小文件结果无覆盖；已有 Clip 保存顺序回归保持通过。

## 3. 一次具名 UI 提交

改动限于 `concat-editor-mcp` 请求/返回契约、`seecut-editor-mcp` 工具、`concat/src/editor_mcp.rs` 桥接，以及画布已有变换/历史的薄类型化适配。可信设置页增加独立临时写授权、短租约和撤销，显示客户端、工程及允许的“移动已选图像层”动作，按现有 i18n 库存补文案；M1 的 R/R+M 不自动升级成写权限。

- 授权含实例、客户端、工程和当前文档会话；每工程最多一个 Agent 写租约，短期到期/撤销即失效。用户仍可正常编辑，Agent 不持 UI 锁。
- 请求包含稳定 image layer ID、文档像素 `dx/dy`、会话、`expectedRevision`、`expectedSelectionRevision` 与 M0 定义的操作身份。数值必须有限且在契约上限内；具体上限由主审在实现前确定，并验证相加后的完整 transform 有效。
- 在同一 UI 提交点核对授权/租约、owner、实例/会话、文档及选择版本、目标存在且可编辑，并且仍是当前单选图像层。存在像素选区、多选、mask 绘画目标、活跃手势/变换、待确认变换或模态状态时明确拒绝；组/调整层及其他目标类型拒绝，不自动选中或移动另一目标。
- 在任何修改前验证完整 X/Y 结果，以已有变换/linked mask/历史规则一次提交、render 与 publish 返回结果。不把两个 `TransformSet` 独立执行成可能半完成的操作；不直接调用缺少结果/变换边界的 `agent_*`，不从桥接直接改 document。
- `dx=dy=0` 返回 `unchanged`，不增 revision、undo 或 dirty。一次有效 X/Y 移动只生成一个 undo 项；失败整体无修改，其他 transform 分量保持。沿现有单调 revision，undo 也产生更新后的版本。重试缓存与最高序号按 M0 上限实现：同操作同参数返回原结果；异参数拒绝；已过序号但结果淘汰返回 `outcomeUnknown`，不重做。

定点测试：授权不足/撤销/过期、另一客户端租约、旧工程/会话/revision/selection、objectGone、busy/待确认变换都零修改；非图像层、选区、多选、mask 目标、已换选择明确拒绝；NaN/Inf/越界或相加后无效 transform 均零修改；稳定 ID 不受展示行变更误指；X/Y 同时有效时恰好一个 undo 并保留旋转/缩放/翻转和 mask 语义；零位移无历史；重复请求仅一次编辑；用户先编辑后旧请求冲突；撤销/重做后旧 revision 仍拒绝。

## 4. 实际运行闭环与资源条件

准备版本归属明确的独立候选、隔离 portable 和小型画布，单选一张图像层，无像素选区及活跃变换。由可信 App UI 授予该具名动作写权限，真实 stdio 请求明确 ID 和小幅文档像素 `dx/dy`；核对返回版本、当前 App 图像位置及其他 transform 分量，再一次 UI undo 同时恢复 X/Y。随后再次平移、实际保存、关闭重开，核对位置/图像和新会话使旧授权及请求失效；零位移、不满足单选前提及撤权另核对无改动。工程写锁实际 native/API 双向拒绝与释放必须另有证据。

CUA 工具仍不可用时，提交实现/单测/构建证据并保留 UI 闭环未知，不能注入 grant 或把测试当原生通过。原生验收需要可操作的工具或用户实际操作及可核对回包。

当前 Data 用量超过项目 256 GB（decimal）上限，本机仅小源码、临时小文件及约 MB 级的 std-only harness；不进行大型 Cargo 构建、下载或打包。大写入前复核 Data 的 `df`、256 GB 项目上限及至少 10 GB 余量；资源恢复或明确授权的等价候选路径确定后才获取新 App。功能分支集中提交并运行受影响宿主/API/桥接测试与实际平台编译，复用有效的历史证据。

## 接续与回退

主审负责目标、所有权/动作契约、产品与授权交互、审查及最终实际验收；Sol/high 负责所有权 helper/测试、native/API 接入及薄适配实现。接入依赖已审契约，不与 helper 不稳定实现并写；写工具最后接入，主代理串行集成并提交验证证据。

每个阶段保留可审阅提交。回退写工具时先移除 capabilities 与授权入口，保留工程所有权保护；回退会话接入须正常停止所有参与 writer，保存未提交状态，不能在活跃进程中解除 owner。M2 仅在实际写入/undo/保存重开闭环及所有权证据成立后接受。
