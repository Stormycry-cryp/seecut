# 视频导出文件的独立核对

状态：内部 worker 已实现，18项成片核对检查通过；H264、HEVC和AV1的8位、10位六种组合均实际编码并完整软件解码通过，错误位深期待均被拒绝。Agent工具与个人库固定版本交付仍待接入。与[输入副本](clip-export-input-snapshot.md)及[导出计划](../plans/2026-10-21-agent-clip-export.md)配合。

## 输入与结果

核对函数仅接收原生控制的实际成片路径、已冻结的输出期望、资源上限和原取消标志。期望包括宽高、正有理帧率、准确视频帧数、视频编码、8位或10位及音频是否应当存在；不得从文件自身反推全部期望，再拿它与自己比较。调用方负责将其绑定原操作及规范化导出选项，模型不能提供路径或证明字段。帧数、结束时间与音频成员由同一renderer的`render_facts`共用计划生成，保留转场后round规则和隐藏/静音尾端；该函数不读取成片或写入输出路径，也不提供发布许可。

该函数可以用于发布前回调收到的完整临时成片，也可以用于已发布文件。失败只说明这次核对未通过，不能自行声称未发布或删除成片。

成功对象的证明字段私有，只能通过实际核对构造；提供只读摘要、内部路径和独立重新核对同内容文件的方法。不接受反序列化的成功对象。内部路径不能直接成为未来模型回执的任意路径能力。

## 必须执行的检查

1. 新开绝对普通文件，拒绝末端软链接和特殊文件；核对句柄与路径的文件身份、修改时间、长度。按块计算 SHA256，长度为正且不超限。
2. 使用 SelfContainedLocal 重新 probe 实际文件，核对实际视频编码、尺寸和准确帧率；音频有无必须与冻结期望一致。probe 成功不能代替整段可读。
3. 使用软件视频 Decoder 从头读到真正 EOF，不用补帧、限帧或循环选项；逐帧核尺寸和非倒退时间位置，准确帧数必须一致，超限立即停止。原生输出为CFR，每帧实际位置须与从0开始的帧序号/帧率一致，允许最多一帧的时间基量化误差；记录实际首末位置，末帧位置加一帧时长也须与冻结预期同容差。不能用名义帧率和帧数代替实际时序核对，也不能只解码首尾两帧。
4. 应有音频时，逐个音频流以 48000 Hz、双声道 F32 流式读至 EOF，检查有限样本、解码采样帧数、实际时长及资源上限，默认最多8个音频流。不把正常静音判成失败；可记录 peak/RMS 供后续验收，但不把这些统计当作已试听。
5. 音频解码时长允许 AAC padding 和一帧视频量化误差，允许误差为 `2048/48000 + 1/fps` 秒；超过则失败。不能通过缩短读取或把全部音频收进内存绕过限制。
6. 解码后再次新开文件并按块计算长度与 SHA256，核对原句柄/当前路径身份及修改状态。前后变化、替换、消失或取消均不能构造成功证明。

默认上限沿输入副本：文件 8 GiB，视频总像素 16777216、单边 8192，帧数 864000，时长 4 小时，正帧率至多 120 fps；哈希块 64 KiB。音频最多按 4 小时加上述格式误差的采样帧数读取。循环逐步检查取消；正在执行的单次系统/解码调用不承诺立即中断。

期望参数先检查有限范围和整数溢出；不直接对未校验有理数调用可能 panic 的构造或乘法。失败和替换测试要使用精确文件/检查点，不依赖 sleep 竞争。

## 可提供的摘要

摘要只陈述实际字节长度、SHA256、视频编码/源帧位深/尺寸/有理帧率/实际解码帧数和时长，以及适用音频的实际编码/探测采样率与声道、标准化解码采样帧数/时长及有限 peak/RMS。它不包含新造的操作、资产或账户身份，不把 probe 的容器 duration 当作准确全段时长。

重新核对相同内容文件时，新开独立普通文件并核长度/摘要/身份即可；字节相同沿用先前完整解码事实，不重复跑整段解码。返回的实际路径状态与核对时间只描述当前检查，不补造原发布历史。移动到最终路径、文件和目录持久化、登记到个人库、固定 AssetReference 及原登记恢复由后续原操作处理。

真实短片覆盖无声与实际混音/mux、H264/HEVC/AV1在当前可用编码器范围内的明确结果、完整视频与音频读取、正确摘要与独立同内容副本；错误尺寸/帧率/帧数/编码/音频预期、被截断或损坏的文件、hash/解码中取消或修改、软链接/特殊文件、字节/帧/时长限制均须失败。必需的 H264 与 AAC 不可用则失败；其他编码器缺失应明确记录测试范围，不能伪称已验证。

## 原始视频帧尺寸约束

完整软件视频读取使用 `Decoder::open_with_source_limits`，传入独立冻结的显示宽高与全局 `max_pixels`。每个 `receive_frame` 成功返回的原始帧必须在下载硬件帧、旋转、缩放、滤镜、seek 丢弃及帧率处理之前检查显示尺寸和像素上限。流元数据与缩放后的输出尺寸不能替代此检查；动态分辨率变化也必须失败。

`AVCodecContext.max_pixels` 在打开 codec 前设为全局像素上限，并在软件回退重新打开时保留。该值不能缩为期望显示宽高的乘积，因为编码尺寸可能包含正常 padding，例如显示 1920×1080 的编码尺寸可能为 1920×1088。此参数是 codec 约束，不是进程内存限制或 sandbox，不能声称约束了容器 probe 或所有 codec 内部分配。旧 Decoder 入口保持既有兼容行为。

## 实际源帧位深

`Decoder::source_bit_depth`报告最近一次成功返回帧对应的实际软件源像素分量位深，在硬件下载后、旋转/缩放/滤镜和RGBA转换前读取FFmpeg静态像素描述。描述缺失、硬件占位或分量深度不一致时返回未知；打开、seek和重新打开后清空，EOF保留最后一次成功事实。它不把待返回的下一帧元信息套到当前帧上。

成片核对要求每个实际源帧均为原请求的8位或10位，未知、混合或不符即失败。该值只证明采样精度；画面质量、HDR、色彩和编码profile仍分别验收。媒体层4项位深检查已包含在80项完整lib内。
