# 视频导出发布与撤销边界

状态：内部控制器已实现，12项实际逻辑检查通过；原生生命周期、导出回执及工具仍待接入。它不新增操作历史，也不构成Agent导出成功证明。当前引擎基础见[导出QA](../testing/main-qa/2026-10-21-clip-export/README.md)。

## 一个原任务的控制权

原生只在原请求仍有效、原许可和原来源核对成功时受理一次导出。单次请求的受理/回复截止时间在受理后结束职责，不能作为整个视频worker的执行截止时间，也不能通过重发原请求延长授权。

worker持有当前App同一Exporter分配的Job，直到实际终态才释放slot；全部停止动作绑定这个Job自己的取消句柄，不使用全局exporter.cancel去取消可能已替换的新任务。已受理操作仍受原账户、会话、文档范围和写权限控制。外部有限lease的原始到期时间继续生效；内置Agent会话没有时钟期限时，仍须响应真实撤权。

普通同工程编辑、选择和预览不撤销已经冻结的导出；它们也不能改变原输入或来源。不得把导出登记进SaveFence的所有before_change钩子。项目关闭/切换、账号/Agent会话变化、显式撤权以及Task暂停/停止在原生事件发起时撤销该原任务，不能等借用Studio成功才处理。

上述生命周期钩子由后续原生适配接入，本批内部原语不能声称已经覆盖这些事件。

## 最终发布资格

内部发布控制器分为唯一、不可克隆的PublishPermit和可克隆的PublishRevoker，共享原Job取消信号；可选deadline仅表示原写lease到期。它没有模型可提供的路径、JSON、账户替代值或新业务操作ID。

共享状态仅包含Pending、Publishing、Revoked及封闭撤销原因。Pending通过同一原子CAS竞争：

- try_claim在原lease未到期且原任务未取消时取得Pending→Publishing，返回不可伪造的发布资格。
- revoke先取得Pending→Revoked时，记录同一次原子状态中的原因，并设置该原Job的取消信号。发布必须拒绝。
- Publishing先取得时，后续revoke返回已开始发布，不改写真实结果或把该任务声称为从未发布。
- 唯一PublishPermit在Pending时被放弃，按abandoned撤销并设置原取消信号；Publishing之后释放不撤销已经开始的事实。

原lease到期时间在CAS前及成功后各采样核对。若线程在两者之间暂停并跨过到期点，返回leaseExpiredAfterClaim，保留Publishing的真实CAS事实，但不返回发布资格；hook据此拒绝实际发布。时钟采样、CAS和文件系统操作无法合成一个硬实时原子动作，不能宣称精确到rename时刻的时钟保证。

取消和发布竞争必须通过Revoker/Permit；原始AtomicBool只是渲染/解码读取的合作停止信号，直接写它不提供同样的发布仲裁。原生接入时必须确认全部适用停止路径使用原Revoker，不能只新增一个末次flag检查就宣称消除发布竞争窗口。

## 文件与登记仍分别核对

同一现有渲染器在完整临时成片就绪后调用一次hook。hook先完成输入清单、实际成片完整解码/摘要及适用文件同步，再取得发布资格；资格必须是hook最后一步。取得资格后底层exclusive publish仍可能失败，Publishing不是文件成功。

实际文件发布后须同步适用目录、独立核同内容最终文件。原后置输入核对失败或取消不能覆盖已经发布的事实；不能把引擎路径返回本身当作成片核对成功。

个人库登记仍沿同一原登记身份。登记前必须核实际prepared副本与原VerifiedOutput摘要，发生在pending journal和commit之前；登记后取得固定AssetReference，并独立核相同版本的受管文件。登记失败保留原输出和原身份，后续只恢复该次登记，不重渲染或创建新操作消除UNKNOWN。

本批内部原语只证明取消与发布资格的竞争，不证明最终文件持久化、个人库、原操作回执或真实App接线。所有成功与未知状态沿将来的原回执保留，不新建第二本业务账本。

## 验证要求

使用精确状态和同步屏障覆盖撤销先成功、发布先成功、竞争仅一个胜者、原lease到期、无期限会话、原任务预取消、permit被放弃、后续任务独立取消信号及Send/Sync实际编译。失败原因必须与最终状态一致，不依赖sleep或放宽时钟边界；普通编辑保持独立由原生集成测试另验。
