# 视频导出的本地输入副本

状态：内部 worker 已实现并通过本地相关检查，真实输入副本与 StrictLocal 渲染检查18项通过。本文不是 MCP 工具、授权协议或视频交付成功证明。Agent 视频导出仍未接入，Android 暂缓。

## 输入与职责

UI 在原许可内捕获原 Project、活动 timeline ID、工程目录、编码选项、同一份 Catalogue，以及可在 worker 使用的标题绘制句柄。文件读取、标题 PNG 绘制、复制、摘要计算和渲染全部在 worker。原生接线由 Astra high 实施。

内部准备函数接收这些可信对象和应用控制的暂存父目录；不接收模型提交的工程 JSON、路径、滤镜字符串或目录清单。活动 timeline 必须精确存在，不能采用 flatten 的回退时间轴。原 Project、Session、原媒体和个人库文件不被重写；标题绘制仍可能按既有 Titles 逻辑写入 PNG/sidecar 缓存，冻结复制不覆盖这些源文件。

本批严格准备选定时间轴的全部片段，包括隐藏或静音片段。缺失 track、media、空媒体路径、标题绘制遗漏、启用但不存在的效果均明确失败。此规则可能比旧手工导出严格；不能默默删除片段改变时间轴结尾。未被选定时间轴引用的媒体不复制。

标题使用实际 Titles 绘制，并逐个核对源文本片段 ID。准备完成时的 PNG 字节进入副本；不承诺这些像素是审批时的字体字节或跨系统完全一致的排版。标题的效果链按捕获的 Catalogue 重建。

## 效果范围

第一批只接受捕获表中无外部目录、无声明 LUT 的内存效果包。音频和视频链均由同一捕获表从结构化 Project 生成，渲染也只读这份表。启用的自定义目录包、声明 LUT 和未知效果明确拒绝，不能静默省略。未启用的效果不参与。

LUT 和任意自定义模板的资源冻结留到后续。不能从 Package 可克隆推断任意 FFmpeg 字面量已经没有外部依赖，也不为导出替换全局 Catalogue。

严格副本导出还须传播实际执行失败。模板能生成非空字符串不证明 FFmpeg 可以执行；普通片段、seek/反向路径和 Layer 任一路解码或效果失败，都不能静默跳过后发布成功。旧手工导出和预览的容错路径保持兼容。首批严格路径采用 CPU 合成和现有 CPU 效果后端，实际编码仍沿原硬件首选与软件回退，不能称为全程软件编码；GPU 像素质量另行验收。

## 复制与资源上限

每次只在应用指定的父目录下以 create-new 语义建立新 job 目录。媒体和标题按原路径去重，流式复制到应用生成的文件名，禁止硬链接。保留有限的安全扩展名用于解码。遮罩按引用的 mask_dir 去重，复制整棵普通目录树，保留数字 PNG、model 和 strokes 相对结构。

拒绝源文件末端软链接、遮罩树内软链接、特殊文件、目录穿越与超过限制的输入。可信父目录先规范化；系统祖先目录软链接不因此一概拒绝。源句柄、复制结果与重新打开的源在长度、摘要以及平台可用的文件身份/修改时间上核对。复制完成后原文件再变化，不改变已复制的输入。

默认上限：输入共 8 GiB，10000 个文件，目录深度 16；单路径 4096 字节、单组件 255 字节；选定时间轴 100000 个片段，源工程编码与清单各 16 MiB；输出每边不超过 8192、总像素不超过 16777216，正帧率不超过 120 fps，时间轴不超过 4 小时且不超过 864000 帧。测试可以使用更小的限制。超额返回明确错误，不能依赖先收集无界目录或整文件读入内存后再判断。

源遮罩目录原本不存在时记录 absent，并把本次请求指向 job 内的空位置，保留旧引擎无现成遮罩时的语义。原本存在但读取或复制失败必须报错。后续原路径出现新遮罩不能影响本次导出。是否抠图正确仍需画面验收。

每个副本记录种类、原来源、受控相对路径、实际长度与 SHA256；目录记录排序后的文件和空目录/absent 状态。源路径仅供内部审计，不作为未来模型回执。清单摘要绑定这些实际副本，不能用工程摘要代替媒体摘要。

准备成功后独立重新打开副本，核对文件、目录形态、数量、大小和摘要。渲染前、渲染后均再次核对同一清单；副本增加、消失、替换或持续改写均报错。取消标志在遍历、复制/摘要分块以及各阶段检查；不能承诺正在执行的单次解码或系统调用立即中断。

暂存对象独占自己创建的 job 目录，在失败或释放时只清理这个目录。确认根仍为原目录后才清理，不删除父目录、原输入、其他 job 或成片。暂存对象应由原导出 worker 持有到实际渲染与后续核对结束。

## 证明边界

准备对象只提供只读请求/清单摘要与核对、渲染方法，不暴露可变请求绕过副本。渲染复用现有 render_with_catalogue_mode_before_publish 并指定 StrictLocal；本批返回的路径仍只是引擎渲染结果，不能称为独立验证成片或个人库交付。错误分别保留渲染前输入无效、引擎失败及其后置核对、引擎已返回成功但后置输入未核实三种事实。第三种必须携带实际已发布路径；后置取消或输入变化不能覆盖已发布事实，普通错误也不证明没有文件。

普通路径副本和前后摘要不能证明同一系统账户的外部进程从未短暂改写又恢复。普通 libavformat 输入可能由容器引用外部资源；严格路径已增加下述媒体格式和额外 I/O 边界，不能只靠复制文件或保留扩展名推断自包含。成片新开与完整解码已单独实现，见[独立核对合同](clip-export-output-verification.md)；原身份授权、发布仲裁及个人库登记恢复仍待原生接线。

媒体策略采用可选 SelfContainedLocal：只预打开受控主副本，主 AVIO 由同一 owner 持有，CUSTOM_IO 和拒绝额外 I/O 的回调在打开容器前设置，配合实际 demuxer 的闭合格式白名单。回调拒绝具有 sticky 状态，读包、seek 和 EOF 都不能吞掉它；probe、paced/seek视频、ReaderPool事实缓存、音频解码、mix及mux贯穿同一策略。MOV显式关闭外部dref/绝对引用；不承诺保留被FFmpeg忽略的外部轨道，也不因此新增通用MOV声明解析器。当前媒体完整76项检查通过，其中7项专门覆盖该输入策略，包含真实H264/AAC、静态图、seek、混音/mux、额外I/O拒绝及文件句柄释放。合法1000Hz PCM WAVE在本机通用probe会误判为MPEGTS，严格主副本根据RIFF/RF64+WAVE字节签名选择wav，原错误场景已重验；不按后缀猜测。FFmpeg未安装DASH demuxer，不能把DASH文本拒绝当作已安装该demuxer的验证。

## 本批验证

真实文件检查覆盖去重、未引用媒体、严格片段/标题完整性、时间轴精确选择、取消、总字节/文件/深度限制、软链接、特殊文件、源变化、副本前后变化、遮罩 strokes 和 absent 状态、失败清理与不触碰其他 job。真实短片测试在副本完成后覆盖写原媒体、标题与遮罩，再用同一捕获表渲染并完整解码核对实际画面和声音；支持范围外的效果必须拒绝。实际 App、模型、GPU 像素、作品质量及正式分发分别待验。
