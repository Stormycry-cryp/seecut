## 行为

- 工作区原同步栏在冲突时提供“保留本机副本”“使用云端”，各有一次简短确认，可取消。两者首先保存完整且可打开的本机恢复项目，采用新 UUID，不继承云 revision、未决上传或同步身份。
- “保留本机副本”：以已确认云 revision 为 CAS 基线上传本机冻结快照，旧云版本继续保留在原不可变历史。“使用云端”：下载确认的 revision，经长度、SHA、路径与受限 ZIP 检查后替换当前项目。两条流程均保留完整本机恢复副本。
- 使用原项目列表、ZIP/SHA、写锁、CAS 和持久 pending。原上传结果未知时只重放原 requestId/原快照/原 baseRevision；拿到匹配回执或明确 CAS 拒绝才清 pending。重复处理中请求拒绝，完成的请求按原 receipt 返回，不再复制或上传。
- 项目打开/聚焦、刷新按钮和同步前真正查询云端列表；并发刷新合并。原 3 秒定时只查看正在同步的本机状态，不新增高频远端轮询。
- 冻结项目、工作区 session、账户/服务 scope + epoch、本地修订和云版本。下载后重新查询云端，最终写锁内重新导出任务记录、比对完整快照；变化就停止。原文件与下载 staging 保留。
- 两次目录 rename 前把恢复事务写入项目索引；异常时回滚，进程中断后下次启动先回滚未提交替换，再开放工作区。索引成功保存是采用云内容的提交点。
- 恢复项目保留节点、连线、文档、视角、相对素材路径/不可变版本及原任务历史。原生任务导出改存为 `.seecut/recovery-native-generation.json`，不把旧付款操作重新绑定到新 UUID；原任务记录仍携带原项目身份，不能作为新项目收费请求继续提交。
- 替换时锁住当前编辑和 MCP 操作；成功后重载工作区，丢弃旧内存缓冲。未知响应使界面暂停编辑并提示重新打开，避免旧缓冲覆盖已采用内容。原生任务记录导入失败仍返回已采用结果，让客户端安全重载，并保留导入重试状态。
