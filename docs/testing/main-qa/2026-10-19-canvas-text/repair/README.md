# C03 定向复核修复

基线 `917a0c0bb578fcde0b8dbcf892162cbfd7ad349e`（初版源码 `009bfa1`）。本次集中处理两处复核问题，保留初版记录与 QA 应用。

## 修复

1. 画布文字新增 `render_layer_frame` 入口，复用字体、排版与绘制；缓存以原文档中心锚点对称扩展，完整包含字形越界、描边、阴影的两次模糊半径和抗锯齿边缘。bitmap 中心仍由现有 LayerTransform 映射一次，不叠加额外对象偏移。左右对齐允许文字暂时在文档画幅外，但缓存像素不会丢失，移动回画布可完整显示。缓存派生于原文字源，保存重开重新构建。时间线 `render` / `render_frame` 保持固定画幅、原锚点与原字号钳制。
2. CanvasText 仍保存 v1 相对数值，放宽验证以支持 UI 的 6–1000px 字号、0–100px 描边和 ±20px 字距，不再套用时间线 0.005–1.0 的相对字号钳制。旧文档的合法数值继续可读。定向覆盖 64、1080、2160 高画布，8px 实际字形高度，以及界面两端字号/描边边界。过大缓存仍有 32768 维度及 512MiB RGBA 上限。

## 证据口径

- `before.log` 留存修复前两个失败：左对齐长行 alpha 总量仅为居中的约 67%，以及小画布的 100px 描边被错误拒绝。
- 字体/标题套件 10 项；画布文字/GPU 6 项。新 GPU 透明背景测试逐像素约束 alpha 差 ≤1/255、预乘颜色差 ≤1/255；极低 alpha 的直通 RGB 会放大舍入误差，相关诊断保留，未改动生产 GPU 算法或其他测试阈值。
- 原生测试单独检验左右/居中长行（含描边、阴影）在正常图层移动后的 PNG、保存重开像素和可编辑源，并复核正式混合导出入库去重。没有重新执行无关的事务/复制/形状全套。
- `alignment-artifacts/` 保存三种对齐的 PNG 和可编辑项目。它们是导出产物，不是 App 截图。
- 新 QA 候选为 `.toonflow/SeeCut-Canvas-Text-Repair-QA.app`；打包后精确源提交、二进制与所有文件摘要记录于本机 `.toonflow/c03-repair/candidate-manifest.json`。初版候选与原 C03 混合工作目录均保留。
